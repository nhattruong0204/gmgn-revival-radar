# OnchainFlow working instructions

For website design, implementation and UI review, use **UI UX Pro Max** as the
primary design skill. Read `.agents/skills/ui-ux-pro-max/SKILL.md`. If missing,
run `python scripts/setup_ui_ux_skill.py` from the repository root. The revision is
pinned in `tools/ui-ux-pro-max.json`; installation preserves existing different
skills and includes the upstream MIT license. Do not replace user design work.

Read `docs/research-ux-workflow.md` and the issue before changing the interface.
Read `design-system/onchainflow/MASTER.md` and the affected page override when
present. If absent, complete the design-foundation issue before a broad restyle;
small targeted fixes can use verified domain guidance. Inspect WSL work and the
actual release base before creating replacements for interrupted changes.
The owner waived unavailable WSL recovery on 2026-10-13 and then requested #40
from the merged #51/#41 foundation. The published base and exception are recorded
in the workflow and design master; do not recreate or reset abandoned local work.

Detect the existing stack: React/TypeScript, Vite and CSS. Apply `--stack react`
for implementation guidance. Skill output is a recommendation: review whether
it fits a research application before persisting it. Do not adopt generated sales
heroes, fabricated proof, forecasts, prices, colors or external font imports by
default. Keep fonts/assets local and preserve licensing and CSP. Do not replace
the framework, install animation/chart packages or change the theme solely because
a search suggests them. Never use `--force` on existing design artifacts without
explicit user authorization.

Keep one scanner, saved-data-only public reads, provider budgets and existing
Telegram delivery. Preserve unknowns, source/time/coverage, historical evidence,
owner boundaries and uncertain-command recovery. Subscriber identity must never
grant owner privileges. Design recommendations do not establish market accuracy,
predictive confidence, safe assets or payment entitlements.

For changed UI, verify relevant component/interaction tests and frontend
build/type/format checks. Include desktop/mobile, keyboard, touch, contrast,
reduced-motion, loading/empty/stale/error/partial and permission-state evidence.
Use the issue's declared browser/load gates; never relax them after seeing results.
Do not access or modify production merely because a UI issue is in progress.
