# [V2][P1] Plain-language call reasons and risks; stop leaking rule keys

**Priority:** P1 · **Complexity:** S · **Labels:** v2, v2-p1, ux, backend, frontend  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

'Why it's on the radar' is always empty for current calls and the token page prints internal keys like `no_base` and `Source: missing_fields.0`.

## Evidence

ALERT_RECORD_CONSISTENCY.md D3/D7; TokenDetail.tsx lines 40–59; token-1366.png.

## Current behavior

Scorer emits only component strings; UI filters them out and shows an empty-state message.

## Proposed behavior / expected outcome

One dictionary mapping component/blocker/warning keys to plain sentences with the measured value (e.g. 'Volume in the last 5 min was 4.1× its baseline ($33K)'). Rank and show top 3 reasons and top 3 risks; keep raw keys in the disclosure.

## Relevant files

- `src/revival_radar/telegram_presentation.py (reuse wording)`
- `web/src/TokenDetail.tsx`
- `web/src/ResearchBrief.tsx`
- `web/src/format.ts`

## Implementation guidance

Derive text from saved values only; unknown evidence can never become a positive sentence (#43 rule).
