# [V2][P0] Reusable CallPerformanceCard component

**Priority:** P0 · **Complexity:** M · **Labels:** v2, v2-p0, ux, frontend  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

Each page renders call facts differently, and none shows performance first.

## Evidence

WEBSITE_UX_REVIEW.md 'Cross-page incoherence'; screenshots signals-1366.png, signal-detail-1366.png.

## Current behavior

No shared call component; Signals rows show symbol/stage/time/score only.

## Proposed behavior / expected outcome

Implement `CallPerformanceCard` (full and compact variants) per V2_ARCHITECTURE §4: dominant MC at call → latest MC and change since call, elapsed, freshness, MFE/MAE, checkpoint strip, stage/score/revision, top reasons/risks, actions.

## Relevant files

- `web/src/components.tsx (or new web/src/CallCard.tsx)`
- `web/src/styles.css`
- `web/src/format.ts`
- `design-system/onchainflow/pages/signal-journal.md`

## Implementation guidance

Follow MASTER.md tokens and UI UX Pro Max workflow (AGENTS.md). 390px-first. Sign + word for direction, never colour alone. Tabular numerals. Pending/missed/unknown states explicit. No new dependencies.

## Dependencies

- #62 (V2-D1) (data); #68 (V2-U4) for reasons text (can stub).
