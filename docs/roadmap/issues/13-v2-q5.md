# [V2][P2] Retain replay-grade evidence and build a point-in-time replay harness

**Priority:** P2 · **Complexity:** L · **Labels:** v2, v2-p2, research  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

Strategy changes cannot be tested against history because evaluations are pruned and candles are limited.

## Evidence

docs/audit/backtest-readiness.md; SEVEN_DAY_SIGNAL_REVIEW.md §8 (not enough data to optimise).

## Current behavior

Pruning removes old evaluations; candle cache is not an archive.

## Proposed behavior / expected outcome

Retain full evaluation payloads for called tokens and a random sample of non-called tokens; keep 1h candles for them. Build a replay harness that re-scores saved inputs with a candidate config, causal by construction, with walk-forward splits. Label candle-only reconstruction as partial.

## Relevant files

- `src/revival_radar/storage/repository.py (pruning)`
- `src/revival_radar/research/replay.py (new)`
- `docs/audit/backtest-readiness.md`

## Implementation guidance

Measure storage growth first; never use future observations; never tune live settings on the evaluation set.
