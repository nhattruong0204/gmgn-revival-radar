# [V2][P0] Data-integrity acceptance suite for published calls

**Priority:** P0 · **Complexity:** M · **Labels:** v2, v2-p0, data-correctness, tests  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

There is no single test suite proving that a call's identity, time and market cap stay consistent from scanner to Telegram, API, Signals, Track Record and Token pages.

## Evidence

Audit requirement §25; parity was verified manually in ALERT_RECORD_CONSISTENCY.md §2 (49/49) but is not enforced by CI.

## Current behavior

Separate tests exist for outcomes, track record and API, but not an end-to-end call contract.

## Proposed behavior / expected outcome

Add `tests/test_call_contract.py` that drives the scanner with fake providers through: evaluation → reservation → delivery → later snapshots → enrichment → API/CSV, asserting the invariants below. Add a read-only `scripts/verify_call_parity.py --db <copy> --api <url>` for production sampling.

## Relevant files

- `tests/`
- `scripts/verify_call_parity.py`
- `src/revival_radar/storage/repository.py (read only)`

## Implementation guidance

Use the existing fake GMGN/Telegram clients. The parity script must open the DB read-only (`mode=ro`) and only issue public GET requests.

## Dependencies

- #62 (V2-D1) (for performance fields).

## Acceptance criteria

- [ ] Call keeps original timestamp/MC after later snapshots and enrichment of the same token.
- [ ] Latest MC comes from a strictly later timestamped observation.
- [ ] Displayed change equals recomputed arithmetic.
- [ ] Missing observation → unknown, not 0.
- [ ] Multiple calls on one token remain distinct with stable IDs.
- [ ] Same call ID in Telegram payload buttons, API, Signals, Track Record, CSV.
- [ ] Strategy preset/revision/score_version stay attached to the original call after settings change.
- [ ] Selected historical cohort is reproducible at a fixed `as_of`.
- [ ] Parity script run against a production copy is attached to the PR.

## Required tests

- The suite itself; plus the parity script's own unit test against a fixture DB.

## Definition of Done

- [ ] Ruff/format/pytest and frontend type/test/build pass in CI.
- [ ] No provider request is added to any public read path; saved-data-only reads preserved.
- [ ] Unknown/missing values render as unknown with a reason, never 0.
- [ ] PR links this issue, #39 and the audit doc it resolves; evidence attached (tests, and screenshots for UI).
