# [V2][P0] Alert pages drop the risk warnings saved with the call

**Priority:** P0 · **Complexity:** S · **Labels:** v2, v2-p0, data-correctness, bug  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

Risks known at publication (bundler penalty, insider holdings unavailable, Token-2022 extensions not assessed) are hidden on the call page, making calls look safer than the saved evidence said.

## Evidence

ALERT_RECORD_CONSISTENCY.md D2. `/api/v1/alerts` item #49: `observation.warnings == []` while `observation.signal.warnings` has entries. Screenshot v2-screenshots/signal-detail-1366.png Risk panel.

## Current behavior

`observation()` in web/queries.py reads `value['warnings']`, which exists for evaluation rows but not for saved alert presentations (they store `signal.warnings` and `token.data_warnings`).

## Proposed behavior / expected outcome

For alert observations, populate `warnings` from `signal.warnings` ∪ `token.data_warnings` (deduplicated, order preserved); keep evaluation behaviour unchanged.

## Relevant files

- `src/revival_radar/web/queries.py`
- `tests/test_web_public.py`

## Implementation guidance

Small, isolated fix. Do not alter stored JSON. Add a regression fixture shaped like a real `telegram:alert:<id>` payload.
