# [V2][P0] Call performance read model: latest market cap, change since call, MFE/MAE

**Priority:** P0 · **Complexity:** M · **Labels:** v2, v2-p0, data-correctness, backend  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

A trader cannot see how a call performed: the product never compares the market cap at the call with the latest observed market cap.

## Evidence

docs/audit/ALERT_RECORD_CONSISTENCY.md D1. Alert #45 shows $4.2M at call and $3.8M latest in separate panels; no API field relates them.

## Current behavior

`/api/v1/alerts` and `/alerts/{id}` return the immutable call snapshot and fixed price checkpoints only.

## Proposed behavior / expected outcome

Add a `CallSummary` model (docs/architecture/V2_ARCHITECTURE.md §4) computed on read from saved `token_snapshots`: latest MC/price/observed_at, freshness, change_since_call_pct, MFE/MAE, observation count, max gap, elapsed, token_call_index/count.

## Relevant files

- `src/revival_radar/web/queries.py`
- `src/revival_radar/web/models.py`
- `src/revival_radar/web/public.py`
- `web/src/types.ts`
- `docs/website-api.md`

## Implementation guidance

Option A in V2_ARCHITECTURE §3: one bounded SQL per page using `snapshots_token_time`; reuse the existing bounded cache and 1.5 s read deadline; cache key includes the latest snapshot time. Change = `(latest_mc/call_mc − 1)·100` only when both are finite and > 0; otherwise `null` + reason (`no_call_mc`, `no_later_observation`). MFE/MAE over `(called_at, latest_observed_at]`. Never read current-state tables into the call snapshot.
