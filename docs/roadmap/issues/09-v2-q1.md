# [V2][P0] Published-call policy: stage gate and evidence-based re-alerts (owner approval required)

**Priority:** P0 · **Complexity:** M · **Labels:** v2, v2-p0, scoring, needs-owner-approval  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

Calls are WATCH-quality and repeat on declining tokens, so the published record is poor.

## Evidence

SEVEN_DAY_SIGNAL_REVIEW.md §2–4: threshold lowered 60→40 at Custom rev 9; 40/43 calls are WATCH; HOOKED called 5× while falling $7.4M→$2.0M; calls ≈ baseline (−17.5% vs −15.2% at 24h).

## Current behavior

`Scanner.process` alerts on `eligible and score >= alert_score_threshold` with no stage condition; `reserve_alert` re-alerts after a 6h cooldown.

## Proposed behavior / expected outcome

Add settings `alert_min_stage` (code default WATCH = current behaviour; recommended value EARLY_REVIVAL) and `realert_requires_new_evidence` (stage upgrade or new HL/HH/breakout and price above previous call). WATCH observations remain on Radar but are not published. Run a 14-day measured trial before/after with the research export.
