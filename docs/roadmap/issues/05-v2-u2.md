# [V2][P0] Track Record as a call performance journal (follow-up to #45)

**Priority:** P0 · **Complexity:** L · **Labels:** v2, v2-p0, ux, frontend, backend  
Epic: #39 · Audit: `docs/audit/ONCHAINFLOW_V2_AUDIT.md`

## User problem

Track Record does not answer 'if I followed previous calls, which moved favourably, which failed, and by how much?'.

## Evidence

WEBSITE_UX_REVIEW.md; `/api/v1/track-record?days=7` returns `median_return_pct: null` (withheld for pooled revisions); page is 6,500 px of checkpoint rows, mostly Pending (track-record-1366.png).

## Current behavior

Unit = checkpoint row; summary withholds medians unless one exact cohort is selected.

## Proposed behavior / expected outcome

Default unit = call (CallPerformanceCard compact rows). Summary: calls, measurable, positive/negative/flat, pending/unknown, median+mean change since call, distribution, MFE/MAE distribution, by stage and by revision — all with denominators. Pooled revisions show descriptive stats labelled 'mixed configurations' instead of 'Withheld'; exact-cohort selection and checkpoint view remain available. Filters: window (24h/7d/30d/all), chain, stage, score range, outcome sign, revision, call age. Sort: newest, best/worst change, MFE, MAE, score, age. Optional group-by-token keeps every call.
